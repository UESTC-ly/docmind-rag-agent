# DocMind v2.2.0 实施与验收

本文档是 v2.2.0 的交付契约。v2.1.0 保留在独立目录中，不在原目录上修改；
v2.2.0 从 `v2.1.0` 标签对应提交派生。

## 总体完成条件

只有同时满足以下条件，v2.2.0 才可发布：

1. 下列九项能力均有实际执行路径，不能只修改文档或把 `blocked` 改为 `ready`；
2. 每项能力至少有一个针对性自动化测试；
3. Python 单元/API 测试、迁移测试、Playwright E2E/视觉测试、Rust 测试及桌面构建检查通过；
4. 原 v2.1.0 目录的提交、已跟踪文件和本地补充资料保持不变；
5. 版本号、变更日志、配置示例和运行文档同步为 v2.2.0；
6. 通过 Lore Commit Protocol 提交，推送独立分支并创建 GitHub draft PR；发布标签只在全部门禁通过后创建。

## R1：生产级 Agent adapters

### 实现范围

- MCP：支持配置化的 Streamable HTTP JSON-RPC 服务，带超时、认证头、服务/工具 allowlist；
- Browser：提供受控 Playwright 会话，支持打开、导航、点击、输入、文本读取和截图；
- App：通过带 token 的本地 HTTP bridge 调用明确允许的应用/动作；
- 所有 adapter 返回统一的 `status/summary/next_actions/artifacts` 观察结构；
- adapter 未配置、未授权或动作越界时安全失败，不回退为伪成功文本。

### 验收证据

- adapter 单元测试覆盖成功、超时、认证、allowlist 拒绝和错误恢复；
- Generic Skill 能通过真实注册表发现并调用 adapter；
- 默认 Web 配置维持最小权限，桌面可信配置显式启用本地能力。

## R2：通用 Skills 能力审计与解锁

### 实现范围

- `docmind.json` 声明 package 所需 capabilities，而非手写静态 `blocked`；
- runtime 根据已实现且已启用的 capabilities 动态判定可用性；
- 增加受控 package script 执行、文本/二进制 asset 读取复制、仓库只读访问和 Git 元数据工具；
- 已有第三方 packages 不再因为“宿主没有对应 action space”永久隔离；缺凭据或本机程序时显示可操作的配置原因。

### 验收证据

- 每个现有 package 都有 capability manifest；
- 测试证明 capability 满足时进入 `all_tools()`，缺失时仍被隔离；
- 不允许通过修改 manifest 绕过宿主权限检查。

## R3：异步评估任务

### 实现范围

- 创建评估 run 后立即返回 `202 Accepted` 与 pending run；
- 评估通过 Celery task 执行，桌面本地模式通过受控本地任务执行器执行；
- 前端轮询 run 状态并显示 pending/running/completed/failed；
- 任务异常保留为失败状态，支持幂等重试且不重复写同一 run 的明细。

### 验收证据

- API 测试证明请求不等待 runner；
- task 测试覆盖成功、失败、重试和重复投递；
- Playwright 测试覆盖评估状态轮询。

## R4：评估复用线上 hybrid retrieval

### 实现范围

- 抽取 async/sync 都能复用的候选融合与 rerank 逻辑；
- 线上 RAG、Skill 检索和 evaluation runner 使用同一检索策略配置；
- EvalResult 保存检索模式、候选来源和可复现的最终排序信息。

### 验收证据

- runner 测试同时验证 dense、keyword、RRF 和 reranker 调用；
- 同一固定语料/问题在在线路径和评估路径产生相同 chunk 顺序。

## R5：二阶段 reranker

### 实现范围

- 默认启用轻量混合信号 reranker；
- 可选 HTTP cross-encoder/rerank provider，配置超时和失败回退；
- reranker 只接收受限候选数，保留原始 rank/score 与最终 score；
- provider 失败时回退到确定性的本地 reranker，而不是让整个问答失败。

### 验收证据

- 排序、稳定 tie-break、候选上限和 provider 回退单元测试；
- RAG sources 与评估明细可看到最终排序分数和召回来源。

## R6：Alembic schema lifecycle

### 实现范围

- 引入 Alembic 配置、基线 migration 和 v2.2 schema migration；
- FastAPI lifespan 不再调用 `Base.metadata.create_all`；
- Web/容器/桌面启动入口在启动 API 前显式执行 `alembic upgrade head`；
- 已有 v2.1 数据库提供安全 adopt/stamp 路径，不能重复建表；
- migration 提供 downgrade，仅把生产回滚视为新的 forward migration。

### 验收证据

- 空数据库 upgrade/downgrade/upgrade 测试；
- 模拟已有 v2.1 schema 的 adopt 测试；
- 搜索确认运行时代码不再自动 `create_all`。

## R7：数据库侧关键词检索

### 实现范围

- PostgreSQL 使用数据库侧全文检索/排名并在 SQL 内 limit；
- 非 PostgreSQL 测试/桌面 SQLite 使用数据库侧 LIKE/BM25 兼容路径，禁止先读取全部 chunks 再排序；
- owner/document 条件进入同一 SQL 查询；
- migration 建立适合生产查询的索引。

### 验收证据

- SQL 构造与结果排序测试；
- 测试证明候选查询有数据库级 limit，且跨用户/文档隔离；
- 大语料 smoke 测试不随用户全部 chunks 建立 Python 列表。

## R8：自动 E2E 与视觉回归

### 实现范围

- Playwright 覆盖注册/登录、上传状态、流式问答、Skills、artifact、异步评估；
- 使用稳定 Page Object、网络等待和可重复 fixture，不使用固定 sleep；
- 提交并在 macOS Chromium 验证视觉基线；Linux/Windows 视觉基线不在本次验收范围；
- CI 失败时上传 HTML report、trace、截图与视频；
- CI 同时执行 Python lint/typecheck、JS 检查、Rust fmt/clippy/test。

### 验收证据

- 本地 Chromium E2E 和视觉测试通过；
- GitHub Actions 包含独立质量与 E2E jobs；
- 视觉基线能检测有意 CSS 变化。

## R9：自包含桌面运行时

### 实现范围

- 桌面生产包通过 PyInstaller sidecar 携带 Python 解释器和后端依赖；
- 桌面配置使用 SQLite、Qdrant local mode 和本地任务执行器，不依赖 PostgreSQL、Redis、Docker 或 uv；
- sidecar 启动前执行 Alembic migration；
- 用户数据、向量、uploads、Skill workspace 与日志继续位于系统可写配置目录；
- 开发模式仍允许使用源码 Python，但不得成为生产 bundle 的必需条件；
- CI 在 macOS 原生 runner 构建 sidecar 和 Tauri 安装包；Windows/Linux 安装包不在本次验收范围。

### 验收证据

- Rust 单元测试验证 production launch 不调用 Docker/uv；
- sidecar smoke test 使用临时 SQLite/Qdrant 目录启动 `/health`；
- 打包检查验证安装包包含 sidecar；
- 文档明确区分外部联网能力所需凭据与本地基础运行时依赖。

## 横切安全约束

- Web 用户不能通过 Generic Skill 获得宿主仓库、任意 shell 或任意应用控制权限；
- 所有外部能力都需要显式 enable、allowlist、超时和审计 trace；
- `user_id` 永远由 DocMind 宿主上下文注入，不能由模型参数覆盖；
- workspace/repository/package 三种文件根目录分别校验，禁止符号链接或路径穿越逃逸；
- artifact 和 adapter observations 设大小上限，不把二进制或密钥回灌 LLM。
