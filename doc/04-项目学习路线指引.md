# DocMind 项目学习路线指引

> 用途：给"想吃透这个项目每一行"的你，一条从零到能独立复述、独立修改的学习路径。
> 按依赖顺序分 8 个阶段，每阶段给：学什么 → 读哪些文件 → 动手验证 → 该能回答的问题。
> 配合 `doc/03-面试100问及回答.md` 使用（下方标注对应题号）。

**学习原则**：不要只"看懂"，要能**用自己的话复述 + 画出数据流 + 改一处并预测结果**。
每个阶段的"动手验证"务必真做，跑不通就是没懂。

---

## 阶段 0：先跑起来，建立整体感（半天）

**目标**：不看代码，先当用户把系统跑通一遍，脑子里有"输入→输出"的完整画面。

**做什么**
1. 按 `README.md` 启动：colima → docker-compose（PG/Redis/Qdrant）→ Celery worker →
   uvicorn。
2. 浏览器开 `http://localhost:8000`，注册 → 上传一个文档 → 等解析完成 → 提问 →
   看流式回答 + 来源。
3. 试 Agent："生成思维导图"；试评估看板跑一次。

**该能回答**
- 这个系统对用户来说能做什么？（→ `doc/01-产品说明手册.md`）
- 一次问答，数据从哪进、经过哪些组件、从哪出？（先凭直觉画，后面验证）

**验证点**：能对着别人用 3 句话讲清 DocMind 是什么、能干什么。

## 阶段 1：项目骨架与配置（0.5 天）

**学什么**：分层架构、配置管理、双数据库引擎的存在意义。

**读文件**（按序）
- `app/main.py` — 入口：注册路由、中间件、静态托管、启动建表。
- `app/config.py` — 配置单例（pydantic-settings 从 .env 读）。
- `app/database.py` — ⭐ 双引擎（async asyncpg / sync psycopg2）、`get_db` 依赖。

**动手验证**
- 在 `config.py` 找出哪些字段是必填的（无默认值）。
- 说清 `AsyncSessionLocal` 和 `SyncSessionLocal` 各给谁用、为什么要两套。

**该能回答**：Q56、Q79。
**验证点**：能画出 `router → service → model` 分层，并说清 async/sync 引擎的分工。

## 阶段 2：鉴权链路（0.5 天）

**学什么**：JWT 原理、密码哈希、依赖注入做鉴权。

**读文件**
- `app/utils/security.py` — 密码哈希 + JWT 编解码（纯函数，最好读）。
- `app/utils/deps.py` — `get_current_user` 依赖，从 token 解出用户。
- `app/routers/auth.py` + `app/services/auth_service.py` — 注册/登录。
- `tests/test_security.py` + `tests/test_auth_api.py` — 看测试怎么覆盖。

**动手验证**
- 手动 `curl` 注册→登录拿 token→带 token 访问 `/auth/me`。
- 把 token 改一个字符，看为什么返回 401。

**该能回答**：Q61、Q62、Q63、Q64。
**验证点**：能解释"JWT 为什么不能放密码"（payload 只是 base64，不是加密）。

## 阶段 3：文档处理与异步任务（1 天）

**学什么**：为什么要异步、Celery 流水线、文档状态机、macOS 的坑。

**读文件**
- `app/routers/documents.py` + `app/services/document_service.py` — 上传：落库 +
  派发任务。
- `app/tasks/document_tasks.py` — ⭐ 解析流水线：提取→分块→存 PG→向量化→写 Qdrant。
- `app/utils/file_parser.py` — 解析与分块（`split_text` 的合并/硬切逻辑）。
- `app/models/document.py` — Document / DocumentChunk 表。

**动手验证**
- 上传文档，在 Celery worker 日志里看任务执行全过程。
- 故意不启 worker，看文档卡在 `pending`——理解为什么。
- 读 `split_text`，手算一个 20 字、chunk_size=10、overlap=2 的输入会切成几块。

**该能回答**：Q3、Q4、Q71、Q73、Q74、Q75。
**验证点**：能画出"上传→pending→processing→completed"的状态机和背后是谁在推动。

## 阶段 4：向量检索与 RAG 核心（1.5 天）

**学什么**：embedding、向量库、RAG 检索→生成链路、数据隔离。

**读文件**
- `app/services/embedding_service.py` — 向量化 + 分批。
- `app/services/vector_store.py` — ⭐ Qdrant 封装：point 设计、upsert、search 过滤。
- `app/services/rag_service.py` — ⭐ 核心：`retrieve` + `answer_question` + `stream_answer`。
- `tests/test_vector_store.py` + `tests/test_rag_api.py`。

**动手验证**
- 说清一个 chunk 从文本到 Qdrant point 的完整字段（id 怎么算、payload 有啥）。
- 找到检索里 `user_id` 过滤那行，理解数据隔离怎么实现。
- 追一遍 `answer_question`：从问题到答案经过哪几步。

**该能回答**：Q1、Q2、Q16、Q18、Q20、Q21、Q24、Q58。
**验证点**：能不看代码画出"问题→向量化→检索→拼Prompt→生成→带来源返回"全链路。

## 阶段 5：多路召回与流式输出（1 天）

**学什么**：混合检索、RRF 融合、SSE 流式、前端为何用 fetch 解析流。

**读文件**
- `app/services/retrieval.py` — ⭐⭐ RRF 融合（纯函数）+ 关键词检索 + 融合合并。
- `app/services/llm_service.py` — ⭐ 流式聚合 + `chat_completion_stream` 生成器。
- `app/routers/chat.py` 的 `/chat/stream` — SSE 端点。
- `tests/test_retrieval.py` + `tests/test_streaming.py`。

**动手验证**
- 手算一个 RRF 例子：两个排名列表，算融合后谁排第一。
- 找到"跨文档 chunk_index 撞 key"那个修复（`_key` 用复合键），理解为什么会撞。
- `curl -N` 打 `/chat/stream`，观察 `event: meta → token → done` 的 SSE 原始输出。

**该能回答**：Q25、Q26、Q27、Q67、Q68、Q69。
**验证点**：能讲清 RRF 公式 + 那个复合键 bug（这是面试最亮的一个具体点）。

## 阶段 6：Agent 编排与技能系统（1.5 天）

**学什么**：Function Calling、ReAct 主循环、可插拔技能设计。

**读文件**
- `app/skills/base.py` + `app/skills/registry.py` — ⭐ 技能基类 + 装饰器注册。
- `app/agent/orchestrator.py` — ⭐⭐ ReAct 主循环（本项目最核心的编排逻辑）。
- `app/agent/memory.py` — 对话历史窗口。
- `app/skills/*.py` + `app/skills/packages/` — Python-backed 技能与 Codex-style 通用包，重点看 `kb_search.py`、`report.py`、`generic.py`、`toolkit.py`。
- `app/services/skill_retrieval.py` — ⭐ 同步 Skill 如何复用向量+关键词 RRF，而不混用 AsyncSession。
- `app/skills/packages/*/docmind.json` — 通用包运行时兼容审计；理解“已安装/已注册/可调用”是三个不同状态。
- `app/services/agent_service.py` — async 层衔接 + 落库。
- `tests/test_agent_orchestrator.py` — ⭐ 看它怎么用假 LLM 测主循环。

**动手验证**
- 追一遍 `run_agent`：LLM 返回 tool_calls → 执行技能 → 塞回结果 → 再循环。
- 追一遍技能卡的 `skill_name`：前端锁定 → API → orchestrator 首轮 `tool_choice`，理解为何它能阻止只在聊天里模拟文件产出。
- 对比 `web_search.py` 与 `packages/codex-note/SKILL.md`，想清楚新增技能的两条路：Python 类 + import，或 SKILL.md 通用包。
- 看 `test_agent_orchestrator` 怎么脚本化假 LLM 逐步返回——理解怎么测一个循环。

**该能回答**：Q29、Q30、Q31、Q32、Q36、Q39、Q42。
**验证点**：能不看代码复述 ReAct 4 步循环，并说清"可插拔"到底插在哪。

## 阶段 7：RAG 评估模块（1.5 天）

**学什么**：怎么量化 RAG 质量、检索指标、LLM-as-judge、基准数据集导入。

**读文件**
- `app/services/evaluation/retrieval_metrics.py` — ⭐ 4 个纯函数指标（最好读）。
- `app/services/evaluation/generation_judge.py` — LLM-as-judge。
- `app/services/evaluation/runner.py` — ⭐ 评估编排：遍历样本→跑RAG→算指标→聚合。
- `app/services/evaluation/dataset_gen.py` — LLM 反向出题。
- `app/services/evaluation/dataset_import.py` — ⭐ 导入 MS MARCO/CMRC（物化成真实文档）。
- `tests/test_eval_runner.py` + `tests/test_eval_api.py`。

**动手验证**
- 手算：relevant={1,2}、retrieved=[1,5,2,9]，算 hit/MRR/recall/precision 四个值。
- 想清楚 dataset_import 为什么必须把 passages 真的 embed 进 Qdrant（否则检索指标怎么算）。
- 跑一次评估，对着结果解释为什么 precision 那么低、hit_rate 和 MRR 差在哪。

**该能回答**：Q43–Q55（这一整块）。
**验证点**：能解释 hit_rate 0.92 / MRR 0.65 的差距含义——这是面试的加分讲法。

**该能回答**：Q87、Q88、Q89、Q90、Q91、Q93。
**验证点**：能讲清"接 CI 时发现测试偷连真库"这个隔离漏洞的故事。

## 学完之后：串起来 + 面试准备

1. **画一张全局数据流图**：从上传到问答到评估，标出每个组件和 async/sync 边界。
   画得出来 = 真懂了。
2. **过一遍 `doc/03` 的 ⭐ 题**，每题不看稿讲 2-3 句 + 举代码例子。
3. **准备 3 个"我踩过的坑"故事**：Celery SIGSEGV、跨文档 key 冲突、测试偷连真库。
   具体的坑最能证明你真做过。
4. **按目标岗位侧重**：后端岗重点讲阶段 1/3/8（架构/异步/工程），
   AI 应用岗重点讲阶段 4/5/6/7（RAG/召回/Agent/评估）。

**总时长**：约 10 天精读。别跳阶段——每一阶段都是下一阶段的地基。
