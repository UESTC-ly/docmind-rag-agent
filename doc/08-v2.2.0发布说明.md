# DocMind v2.2.0 发布说明

发布日期：2026-07-13

v2.2.0 把此前的扩展点和开发级实现收束为可执行、可迁移、可自动验证的两种部署形态：
Web 继续面向服务端开发与部署；桌面安装包改为自包含本地运行时。两者共享业务 API、
检索、Skills 与评估语义，但使用不同的基础设施配置。

## 主要变化

### Agent 与通用 Skills

- Streamable HTTP MCP adapter 支持 JSON/SSE 响应、session 初始化、环境变量 bearer token、
  server/tool allowlist 和超时。
- Playwright adapter 提供按 execution 隔离的浏览器会话、域名 allowlist，以及限制在 Skill
  workspace 的截图产物。
- App adapter 只连接 loopback HTTP bridge，并要求 token 与 application/action allowlist。
- adapter observation 统一为 `status`、`summary`、`next_actions`、`artifacts`；失败会说明
  root cause、重试建议与停止条件。
- 复制进来的 Skills 使用 `docmind.json.requires` 声明能力。包可以通过审计成为 `ready`，
  但只有宿主显式授权并满足全部 capability 后才会进入 Agent 工具列表。
- 新增 package asset/script、只读 repository/search 与 Git history 工具；三类文件根目录相互隔离。

### 检索与评估

- 在线 RAG、Skills 与 evaluation runner 统一走 dense + database keyword candidates、scored RRF
  与 reranker，不再让评估只测 dense path。
- PostgreSQL 关键词召回改用全文检索和排名；SQLite 使用 SQL-side compatibility scorer。
  两条路径都在数据库中应用 user/document 过滤、排序和 `LIMIT`。
- 默认 local reranker 确定性组合 RRF、dense、keyword 与词项重合信号；可选 HTTP
  cross-encoder，provider 失败时自动回退 local。
- `POST /eval/runs` 返回 `202 Accepted`。Web 使用 Celery，桌面使用本地任务执行器；前端
  轮询 run 状态。EvalResult 保存 retrieval/reranker 模式、来源、原始分数和最终顺序。

### Schema 与自动化

- Alembic 成为唯一运行时 schema 管理路径。包含 v2.1 baseline 与 v2.2 search/eval trace
  migration；FastAPI 不再通过 ORM metadata 自动建表。
- PostgreSQL migration 使用 GIN expression index 支撑 `to_tsvector('simple', content)` 查询。
- Playwright 覆盖登录、上传状态、流式问答、Skills/artifact、异步评估，以及 Chromium 视觉基线。
- CI 分别执行 Python lint/typecheck/tests、JavaScript syntax、Rust fmt/clippy/test 和 Chromium
  E2E/视觉；失败保留可复现 artifacts。

### 桌面运行时

- Tauri 安装包携带 PyInstaller 冻结的 `docmind-sidecar`，内含 Python、FastAPI 与后端依赖。
- 桌面使用 SQLite、Qdrant local、local task executor 与 Alembic；数据落在用户应用数据目录。
- 终端用户不需要 Docker、PostgreSQL、Redis、Qdrant Server、uv 或系统 Python。
- OpenAI 兼容聊天/embedding 服务仍是外部服务，需要用户配置凭据并可联网；这是模型能力依赖，
  不属于本地基础运行时。

## Web 与桌面边界

| 项目 | Web 源码运行/服务部署 | 已安装桌面 App |
|---|---|---|
| 数据库 | PostgreSQL | SQLite |
| 向量存储 | Qdrant Server | Qdrant local |
| 后台任务 | Redis + Celery | bounded local executor |
| Python 后端 | Python 3.12 + uv 环境 | PyInstaller sidecar 内置 |
| Docker | 本地一键脚本默认使用 | 不需要 |
| Alembic | 启动器与 lifespan upgrade | sidecar 首次/每次启动 upgrade |
| AI/embedding | 外部 OpenAI 兼容服务 | 外部 OpenAI 兼容服务 |

不要把“桌面自包含”理解成 Web 开发也不需要基础设施；也不要把 build runner 的 Node、Rust、
Python 需求误写成终端用户安装要求。

## 从 v2.1 升级 Web 数据库

1. 停止写入并备份 PostgreSQL 数据库。
2. 核对现有表/枚举/索引与 v2.1 baseline 一致；漂移库先修复，不要直接 stamp。
3. 仅对已有 v2.1 `create_all` 数据库执行：

   ```bash
   uv run alembic stamp 0001_v210_baseline
   uv run alembic upgrade head
   ```

4. 新数据库不要 stamp，直接执行：

   ```bash
   uv run alembic upgrade head
   ```

5. 启动 API 与 Celery，检查 `/health`、上传任务和异步评估。

v2.2 的 PostgreSQL FTS index 使用独立的 `CREATE INDEX CONCURRENTLY` revision。若
migration 中断，直接重跑 `alembic upgrade head`：前一个事务性 revision 已提交并 stamp，
索引 revision 会自动删除 invalid index 后重建；若同名有效索引定义不同则明确失败，不能
把漂移 schema 直接 stamp 成成功版本。详细恢复规则见 `alembic/README.md`。

## 桌面安装与构建

终端用户安装对应 OS/架构的正式包，首次运行后编辑应用数据目录里的 `desktop.env`，至少设置
真实 `OPENAI_API_KEY`，然后重启 App。数据库、向量、uploads、Skill workspace、JWT key 和
日志独立于安装包，升级/卸载不会主动清理。

构建发布包：

```bash
cd desktop
npm ci
npm run build
```

构建机需要 Node 22、Rust 与 Python 3.12+；`npm run build` 会冻结、自检和 smoke sidecar，
再构建 Tauri installer。PyInstaller 不能跨平台冻结原生扩展；v2.2 本次只验证 macOS，
Windows/Linux 不在验收范围。仓库默认使用 Tauri ad-hoc identity（`-`）保证
Apple Silicon 本地包具有完整签名；对外正式发布仍需要 Developer ID 签名与 Apple 公证凭据。

发布前应在未安装 Docker、uv、Python、PostgreSQL、Redis、Qdrant Server 的干净机器/VM 上验证：

1. 首次启动和 Alembic migration；
2. 注册/登录、文档上传与后台完成；
3. 重启后文档、向量检索和任务状态仍可用；
4. 异步评估从 pending/running 进入终态；
5. 应用升级后用户数据目录保持不变。

## 可选能力配置与默认安全性

Web 默认不启用 repository、package scripts、MCP、browser 或 App 控制。按需配置以下组，并
保持最小 allowlist：

- `SKILL_REPOSITORY_ENABLED`、`SKILL_REPOSITORY_ROOT`
- `SKILL_PACKAGE_SCRIPTS_ENABLED`、`SKILL_PACKAGE_SCRIPT_*`
- `SKILL_MCP_ENABLED`、`SKILL_MCP_SERVERS_JSON`、`SKILL_MCP_TIMEOUT_SECONDS`
- `SKILL_BROWSER_ENABLED`、`SKILL_BROWSER_ALLOWED_HOSTS`、`SKILL_BROWSER_TIMEOUT_SECONDS`
- `SKILL_APP_ENABLED`、`SKILL_APP_BRIDGE_URL`、`SKILL_APP_BRIDGE_TOKEN`、
  `SKILL_APP_ALLOWED_ACTIONS_JSON`

缺配置时相关 Skill 显示具体 missing capability，而不是永久 blocked；这不应通过扩大默认权限
来“修复”。任意外部 adapter 仍需部署者负责服务健康、凭据轮换和操作系统授权。

## 验证命令

```bash
uv run pytest --cov=app --cov-report=term-missing

cd frontend
npm ci
npm run test:e2e

cd ../desktop
npm ci
npm run test:sidecar
npm run test:rust
```

发布结论以当前分支实际命令输出、安装包 smoke 和 GitHub Actions 为准，不沿用旧版本的测试数量、
覆盖率快照或“当前绿”陈述。

## 已知边界

- 脑图/关系图谱仍读取顺序正文窗口，尚未实现超长文档全文 map-reduce。
- HTTP reranker、MCP、浏览器、App bridge 与 AI provider 都是显式配置的外部边界；默认关闭或
  provider 失败回退是预期行为。
- 公开评估数据导入、embedding 和 LLM judge 可能产生外部 API 成本。
