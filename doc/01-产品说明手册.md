# DocMind 产品说明手册

> 面向 DocMind v3.1.0 使用者的操作手册。讲清“这是什么、能做什么、怎么用”。
> 面向开发者的架构与配置细节见项目根目录 `README.md`。

---

## 一、DocMind 是什么

DocMind 是一个 **Agentic 文档智能问答系统**。你把文档（PDF / Word / 文本 / Markdown）
上传进来，它会自动解析、切块、向量化，之后你就能用自然语言就文档内容提问。

它不只是"检索 + 回答"，而是由一个 **AI Agent** 自主判断该做什么：
该查知识库、还是画思维导图、还是抽关系图谱、还是写报告、还是联网搜索——由 Agent
根据你的问题自己决定调用哪个能力。

一句话：**把一堆文档，变成一个能对话、能画图、能写报告的智能助手。**

---

## 二、核心能力一览

| 能力 | 说明 | 触发方式（自然语言即可） |
|---|---|---|
| 知识库问答 | 基于文档内容回答问题，附来源引用 | "这份文档讲了什么？" |
| 思维导图 | 提炼文档层级结构，输出可渲染的脑图 | "把这篇文档做成思维导图" |
| 关系图谱 | 抽取文档中的实体和关系（GraphRAG） | "画出文档里各概念的关系图" |
| 报告生成 | 检索 → 列大纲 → 逐节成文 | "就 XX 主题写一份报告" |
| 联网搜索 | 知识库答不了时补充外部信息 | "查一下最新的 XX" |
| 流式回答 | 答案逐字浮现，无需等全文生成 | 所有问答自动生效 |
| 质量评估 | 量化"检索准不准、答得好不好" | 评估看板一键运行 |

## 三、界面导览

前端是一个极简风格的单页应用，左侧导航 + 右侧主区。三个主视图：

### 1. 对话（首页）

- 中间是对话流，你的问题在上、DocMind 的回答在下。
- 回答**逐字浮现**（流式），末尾带一个闪烁光标，生成完自动停止。
- 回答下方是**来源引用卡**：显示这条答案参考了哪个文档的哪一片段、相关度分数。
- 底部输入框：**Enter 发送，Shift+Enter 换行**，输入框会随内容自动长高。
- 左侧"会话"列表可切换历史对话，点"＋ 新对话"开一段新的。

### 2. 文档

- 顶部是上传区：**拖文件进去，或点击选择**。支持 PDF / Word / TXT / Markdown。
- 上传后文档进入列表，状态会自动刷新：
  - `待解析` → `解析中`（带脉冲动画）→ `已完成` / `失败`
  - 只有 `已完成` 的文档才能被问答检索到。
- 每个文档显示：文件名、编号、分块数、上传时间，右侧可删除（连带清理向量）。

### 3. 评估

- 列出所有评估数据集（LLM 自动出题生成的，或导入的公开基准）。
- 每个数据集有"运行评估"按钮，点击后系统逐条跑 RAG + LLM 打分。
- 完成后展示 6 个指标的**条形可视化**：
  - 检索类：命中率、MRR、召回率、精确率
  - 生成类：忠实度、答案相关性

## 四、上手五步

> 前提：管理员已按 `README.md` 启动好后端服务（PostgreSQL / Redis / Qdrant /
> Celery worker / API）。浏览器打开 `http://localhost:8000`。

1. **注册 / 登录**：首屏输入邮箱 + 密码（≥6 位），首次点"注册"切换到注册模式。
2. **上传文档**：进"文档"视图，拖入一个 PDF 或文本文件。
3. **等待解析**：看着状态从"解析中"变成"已完成"（小文件几秒，大文件稍久）。
4. **提问**：回到"对话"视图，输入"这份文档讲了什么？"，看答案逐字浮现。
5. **进阶**：试试"把这篇文档生成思维导图"，Agent 会自动调用对应技能。

## 五、使用建议与边界

**建议**
- 问题尽量具体。"存储层用了哪些组件？"比"讲讲这个"检索效果更好。
- 想限定只问某一篇文档时，先在文档列表确认它已"已完成"。
- 生成报告 / 图谱这类任务耗时更长（多次调用大模型），耐心等待流式输出。
- 高风险 Skill 会先显示待审批内容；确认参数后再批准。不要在不理解外部副作用时直接批准。

**边界与注意**
- 回答**严格基于已上传文档**。文档里没有的信息，系统会明确说"无法回答"，
  而不是编造——除非它主动走了联网搜索。
- 首次上传若一直停在"待解析"，通常是后台 Celery worker 没启动，联系管理员。
- 评估中的 `precision` 偏低是指标定义使然（top-k 召回多、单题相关块少），
  不代表系统差；重点看 `hit_rate` 和 `MRR`。
- 若同一个 Agent 任务显示“另一个 worker 正在执行”，不要新建任务；稍后使用原任务状态继续。
  v3.1 会保留客户端 run ID，避免并发重试造成重复工具调用。

## 六、常见问题（FAQ）

**Q：支持哪些文件格式？**
A：PDF、Word（.docx/.doc）、纯文本（.txt）、Markdown（.md）。

**Q：上传的文档别人能看到吗？**
A：不能。所有数据按用户隔离，向量检索强制按用户过滤，接口校验资源归属。

**Q：为什么回答里有"来源"？**
A：这是 RAG 的可解释性——让你知道答案的依据来自文档哪一段，便于核对，减少盲信。

**Q：答案是实时生成的吗？**
A：是。采用流式输出（SSE），逐 token 推送，你能看到答案一个字一个字出现。

**Q：评估模块是做什么的？**
A：量化问答质量。检索指标衡量"有没有找对文档片段"，生成指标（LLM 当裁判）衡量
"答得忠不忠实、切不切题"。这是判断系统好坏、做优化对比的依据。

**Q：为什么 Agent 偶尔提示任务被锁定？**
A：同一 `run_id` 已由另一个 Web worker 或桌面进程推进。系统返回可重试冲突而不是并发执行，
是为了防止审批恢复、工具副作用或 checkpoint 被重复写入。等待后读取原任务即可。
