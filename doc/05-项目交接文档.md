# DocMind 项目交接文档

> 用途：让接手者（人或 AI）快速掌握项目全貌、当前状态、关键约定与发布边界。
> 最后更新：2026-07-13（v2.2.0）。以本文档、根目录 `README.md` 和当前代码为准；冲突时以代码为准。

## 0. 一分钟速览

- **是什么**：Agentic RAG 文档智能系统。上传文档后，Agent 用 Function Calling 编排
  Python-backed 与 Codex-style Skills，输出问答、脑图、图谱、报告、周报、PPT 等结果。
- **检索**：在线问答、Skills、评估统一使用 dense + 数据库关键词 + scored RRF + reranker。
- **评估**：`POST /eval/runs` 返回 `202 Accepted`，Web 交给 Celery，桌面交给本地任务执行器，
  前端轮询 pending/running/completed/failed。
- **部署**：Web 源码运行使用 PG/Redis/Qdrant/Docker/uv/Python；安装后的桌面 App 使用
  Tauri + PyInstaller sidecar + SQLite + Qdrant local，不要求终端用户安装上述基础运行时。
- **仓库**：<https://github.com/UESTC-ly/docmind-rag-agent>。
- **质量状态**：Python、JavaScript、Rust、Playwright E2E/视觉门禁已经接入；不要在文档中
  写死测试数量或覆盖率快照，发布状态以当前本地命令和 GitHub Actions 结果为准。

## 1. 架构与关键数据流

```text
FastAPI (async) ──► Agent Orchestrator ──► Skills
     │                       │                │
     ├──────────────► shared retrieval ◄─────┘
     │               dense + DB keyword
     │                 RRF + reranker
     ▼
Web: PostgreSQL + Qdrant Server + Redis/Celery
Desktop: SQLite + Qdrant local + local task executor
```

接手者必须跑通以下五条路径：

1. **上传**：`POST /documents/upload` → `dispatch_document()` → Celery/local executor →
   解析、分块、embedding、Qdrant upsert → pending/processing/completed/failed。
2. **问答**：`POST /chat/` 或 `/chat/stream` → dense + DB keyword candidates → scored RRF →
   local/HTTP reranker → Prompt → LLM → answer + 带检索诊断的 sources。
3. **Agent**：`POST /agent/chat` → ReAct tool loop。技能卡传 `skill_name` 时强制首轮技能；
   文档已选且未锁定技能时，首轮走 `search_knowledge_base`。
4. **Skills**：package manifest 声明 `requires`；host capability gate 决定当前进程是否可用。
   生产 MCP、Playwright 与 loopback App adapters 统一返回结构化 observation。
5. **评估**：创建 pending run → 后台任务调用共享检索和生成 judge → 保存逐样本 retrieval trace
   与聚合指标 → 前端轮询终态。

## 3. 启动与迁移

### 3.1 Web 开发/服务部署

前置：Python 3.12、uv、Docker/Compose；macOS 可用 Colima。该要求不适用于安装后的桌面 App。

```bash
# macOS / Linux
./start.sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

启动器会创建/同步 venv、启动 PG/Redis/Qdrant、执行 `alembic upgrade head`、启动 Celery，
再启动 FastAPI。手动路径：

```bash
docker compose up -d
uv venv --python 3.12 .venv
uv pip install -r requirements.txt
uv run alembic upgrade head
uv run celery -A app.celery_app worker --loglevel=info --pool=solo
uv run uvicorn app.main:app --reload --port 8000
```

Web 模式的文档解析和评估运行都需要 Celery。FastAPI lifespan 也会幂等执行 migration，
但启动器显式迁移可以更早暴露错误。运行时代码不得恢复 `Base.metadata.create_all`。

### 3.2 从 v2.1 已有数据库接管

v2.1 数据库由 `create_all` 建成，没有 Alembic version。先备份并确认 schema 与 v2.1 基线一致，
然后只执行一次：

```bash
uv run alembic stamp 0001_v210_baseline
uv run alembic upgrade head
```

新数据库不能 stamp，应直接 `uv run alembic upgrade head`。事务性列变更与 PostgreSQL FTS
`CONCURRENTLY` 索引是两个 revision；若构建中断，索引 revision 会在重试时自动清理
invalid index，若同名有效索引的定义不同则拒绝静默接管。恢复规则见 `alembic/README.md`。

### 3.3 桌面生产运行时

安装包启动 `docmind-sidecar`，宿主强制注入：

```text
DATABASE_URL=sqlite+aiosqlite:///<app-data>/data/docmind.db
QDRANT_PATH=<app-data>/data/qdrant
TASK_EXECUTION_MODE=local
```

sidecar 内含 Python/FastAPI 依赖，启动时迁移 SQLite，并将 uploads、Skill workspace、密钥
和日志保存在用户应用数据目录。终端用户不需要 Docker、PostgreSQL、Redis、Qdrant Server、
uv 或系统 Python；仍需配置 OpenAI 兼容聊天/embedding 凭据与网络。

构建机需要 Node、Rust、Python 3.12+：

```bash
cd desktop
npm ci
npm run build
```

PyInstaller 不跨平台冻结原生扩展。v2.2 本次发布门禁只验证 macOS 原生 runner 和安装包；
Windows/Linux 不在本次验收范围。macOS 本地构建默认采用 Tauri ad-hoc identity（`-`）；
对外发布仍需 Developer ID 签名/Apple 公证凭据，并应在没有 Docker/uv/Python 的干净
macOS 机器或 VM 上做安装冒烟。

## 4. v2.2 关键设计决策

| 决策 | 原因与约束 |
|---|---|
| **共享 hybrid retrieval** | 在线、Skill、eval 不能使用三套不同排序；统一保留 dense/keyword/RRF/rerank 诊断 |
| **PG FTS + SQLite SQL fallback** | 两种路径都在 DB 内过滤、排序、limit；禁止先加载用户全部 chunks |
| **local reranker 默认启用** | 无新模型依赖、稳定 tie-break；HTTP cross-encoder 失败时回退 local |
| **异步评估 run** | 创建请求立即返回 202，长数据集不会占用 HTTP；runner 对重投递幂等 |
| **Alembic 唯一 schema 路径** | baseline 接管旧库，v2.2 migration 添加 trace 与 FTS index；启动失败关闭 |
| **manifest 只声明需求** | `status: ready` 不是权限；host capability gate 才能授权仓库、脚本、MCP、浏览器、App |
| **adapter 最小权限** | MCP service/tool allowlist；browser host allowlist；App 仅 loopback + token + action allowlist |
| **桌面 runtime 设置不可被 dotenv 覆盖** | 防止旧配置让安装包悄悄连回 Docker/网络数据库 |

安全铁律：Qdrant payload 带 `user_id`；SQL keyword query 通过 Document join 过滤 owner；
`user_id` 由宿主上下文注入；workspace、package、repository 三类根目录分别做路径/符号链接校验；
adapter observation 和 artifact 有大小限制，密钥不回灌 LLM。

## 6. 当前状态与剩余风险

v2.2 已实现此前列出的九项缺口：生产 adapters、动态 capability manifests、异步评估、
评估复用 hybrid RRF、reranker、Alembic、数据库侧关键词、自动 E2E/视觉、自包含桌面 sidecar。

这些不是代码缺口，但仍是发布/运维责任：

1. **外部能力配置**：MCP、远端 reranker、浏览器、App bridge、OpenAI/embedding 服务需要
   部署者显式提供 URL、凭据、allowlist 或本机运行时；默认关闭是安全设计，不是 blocked 回归。
2. **桌面签名与干净机验证**：每个平台的正式安装包需要签名/公证，并在无开发工具链机器验证。
3. **旧库接管**：v2.1 只允许在 schema 核对/备份后 stamp baseline；不要盲目 stamp 漂移库。
4. **长文档结构化技能**：脑图/图谱仍是顺序正文窗口，全文 map-reduce 是未来增强，不能声称已覆盖全文。
5. **评估数据成本**：公开数据集导入、embedding 与 LLM judge 可能产生外部 API 费用。

## 8. 协作约定

- 先给可复现证据，再改代码；错误排查优先完整 traceback、请求/任务 id 与任务日志。
- 改检索必须验证 online、Skill、eval 三条调用路径排序一致；不要只修其中一处。
- 改 schema 必须新增 migration 与 downgrade，不能改写已发布 revision 或恢复 runtime `create_all`。
- 改 Generic Skill 权限必须同时检查 manifest、capability gate、tool root confinement 和 tests。
- 桌面改动要区分 build-time toolchain 与 end-user runtime；不要重新引入 Docker/uv/Python 探测。
- 提交遵循仓库 AGENTS.md 的 Lore Commit Protocol，并如实记录 Tested / Not-tested。
