## 0. 一分钟速览

- **是什么**：Agentic RAG 文档智能问答系统。上传文档 → Agent 用 Function Calling 自主
  编排 8 个可插拔技能（问答/思维导图/关系图谱/报告/周报/PPT/联网/通用包）→ 流式回答，附来源引用。

  Celery · Redis · 原生单页前端。

- **仓库**：https://github.com/UESTC-ly/docmind-rag-agent （公开，账号 UESTC-ly，分支 `main`）。
- **CI**：GitHub Actions，push/PR 触发，pytest + 90% 覆盖率门槛，**当前绿**。
- **本地路径**：以实际 clone 目录为准；本文档示例默认位于仓库根目录。

## 2. 架构总览

```
                   ┌───────────────────────────────────────────┐
  HTTP (JWT)       │            FastAPI (async)                 │
 ───────────────► │  routers → services → models / schemas     │
                   └──────┬──────────────────────┬──────────────┘
                          │                       │
           ┌──────────────▼────────┐   ┌──────────▼─────────────┐
           │  Agent Orchestrator    │   │  RAG (chat / stream)   │
           │  ReAct 主循环          │   │  多路召回→Prompt→LLM   │
           │  Function Calling      │   └──────────┬─────────────┘
           └──────────────┬────────┘              │
                          │ 调度                   │
           ┌──────────────▼─────────────────────┐ │
           │  Skills（装饰器注册，可插拔）        │ │
           │  Python Skills + Codex-style packages │ │
           └──────────────┬─────────────────────┘ │
   ┌──────────────────────▼─────────────────────────▼─────────────┐
   │  PostgreSQL(元数据/分块)  Qdrant(向量)  Redis(队列)           │
   └───────────────────────────────────┬───────────────────────────┘
                            ┌───────────▼────────────┐
                            │  Celery Worker           │
                            │  解析→分块→向量化→写库   │
                            └──────────────────────────┘
```

**四条关键数据流**（接手者务必在脑中跑通）：
1. **上传**：`POST /documents/upload` → 落库 + `process_document.delay()` → Celery 后台
   解析/分块/向量化 → 状态 pending→processing→completed。
2. **问答**：`POST /chat/` 或 `/chat/stream` → `retrieve()`（向量+关键词 RRF 融合）
   → 拼 Prompt → LLM → 带 sources 返回（流式则逐 token SSE）。
3. **Agent**：`POST /agent/chat` → `run_agent()` ReAct 主循环 → LLM 返回 tool_calls
   → 执行技能 → 塞回上下文 → 循环至最终答案。
4. **评估**：`POST /eval/runs` → `runner.run_evaluation()` 遍历样本跑 RAG + 算检索指标
   + LLM-judge → 聚合存 EvalRun。

## 4. 如何启动（本地开发）

**前提**：Python 3.12 + uv + Docker。macOS 推荐 Colima；Windows 推荐 Docker Desktop；
Linux 使用 Docker Engine + Compose。`.env` 不入库，首次启动脚本会从 `.env.example` 创建。

```bash
# macOS / Linux
./start.sh
```

```powershell
# Windows PowerShell
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

启动脚本会：检查依赖 → 创建/同步 `.venv` → 启动 PG/Redis/Qdrant → 等 PG 可达 →
后台启动 Celery worker → 前台启动 `uvicorn`。浏览器打开 `http://localhost:8000/`。

手动启动时核心命令：

```bash
docker compose up -d
uv venv --python 3.12 .venv
uv pip install -r requirements.txt
uv run celery -A app.celery_app worker --loglevel=info --pool=solo
uv run uvicorn app.main:app --reload --port 8000
```

macOS 若手动启动 Celery，需额外加：

```bash
OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES \
  uv run celery -A app.celery_app worker --loglevel=info --pool=solo
```

**测试**：`uv run pytest --cov=app`。push 前建议 `source .venv/bin/activate`，因为
pre-push hook 会用当前 venv 的 pytest。

## 5. 关键设计决策与"为什么"

| 决策 | 原因 |
|---|---|
| **async + sync 双 DB 引擎** | FastAPI async(asyncpg)，Celery 同步(psycopg2)；铁律：别混用 |
| **同步调用包 `asyncio.to_thread`** | OpenAI/embedding/Qdrant 都是同步的，直接在 async 里调会阻塞事件循环 |
| **文本存 PG、向量存 Qdrant** | 各司其职；用 `(document_id, chunk_index)` 关联两边 |
| **多路召回 RRF 融合** | 向量擅长语义、关键词擅长精确匹配，互补；RRF 免归一化 |
| **融合用 `(document_id, chunk_index)` 复合键** | chunk_index 仅单文档内唯一，跨文档会撞键（真实修过的 bug） |
| **检索指标做纯函数** | 无 I/O、易单测、100% 覆盖 |
| **Skills 装饰器注册** | 开闭原则：新增技能 = 写类 + 一行 import，核心零改动 |
| **LLM 统一走 stream=True** | 中转 gzxsy.vip 强制流式，非流式会返回 str 导致 `.choices` 报错 |
| **前端 SSE 用 fetch 非 EventSource** | EventSource 不能带 Authorization 头，而 /chat/stream 要 JWT |
| **datasets 惰性导入** | HuggingFace datasets 是重型可选依赖，未进 requirements，纯解析/测试不需要它 |

## 6. 环境坑（都已解决，接手者别重复踩）

1. **Celery macOS SIGSEGV**：默认 prefork 池 fork 原生扩展崩溃 → `--pool=solo`。
2. **中转强制流式**：`gzxsy.vip` 无视 stream 参数 → `llm_service` 统一 stream=True 聚合。
3. **eval 接口返回旧快照**：async session `expire_on_commit=False` + 跨 sync 提交 →
   重查前 `db.expire_all()`。
4. **coverage 假性偏低**：async 端点行未被追踪 → `.coveragerc` 加 `concurrency=greenlet,thread`。
5. **测试偷连真 PG**：`test_chat_reuses_conversation` 经 load_history 连真库 → mock 掉。
6. **CI 缺 datasets 库**：本地手动装过所以没暴露 → 惰性导入解耦。
7. **bcrypt 版本**：钉死 4.0.1（passlib 1.7.4 与 bcrypt 5.x 不兼容）。
8. **EMBEDDING_DIM 必须与模型一致**：换 embedding 模型要重建 Qdrant collection。
9. **DashScope embedding 会欠费**：Arrearage 错误 = 余额不足，非代码问题。

## 7. 当前状态与已知缺口

**已完成**：五阶段路线 + 评估模块 + Phase 7（多路召回/流式/结构化日志）+ 前端 + Codex-style 通用 Skills +
185 测试/94% 覆盖 + CI（绿）+ 已发布公开仓库 + 5 份文档。

**已知缺口 / 后续方向**（优先级从高到低）：
1. **检索加 rerank**（cross-encoder 重排）——针对 MS MARCO 上 MRR 偏低（0.65 vs hit 0.92）。
2. **评估运行改异步**（当前同步阻塞，大数据集会超时）——改 Celery task + 进度轮询。
3. **Alembic 迁移**——当前靠 `create_all` 建表，仅开发级。
4. **关键词检索下推 DB**——当前内存全表打分，大规模会崩，应上 PG 全文索引/ES。
5. **前端视觉回归测试**——Playwright 未装（截 320/768/1440 断点）。
6. **E2E 自动化**——目前只手动冒烟过。
7. **requirements 补 datasets**——若要在 CI 跑评估导入功能，需显式加 `datasets pandas pyarrow`。

**GitHub 相关注意**：gh token 缺 `workflow` scope，**改 `.github/workflows/` 下文件
无法本地 push**，需网页 UI 编辑，或 `gh auth refresh -h github.com -s workflow`（交互授权）。

## 9. 作者与协作偏好（供接手 AI 参考）

- 作者 Python 初级、备战 2026 秋招，**要求真正掌握每行代码、能独立复述和修改**，
  不接受"我写你抄跑通就行"。带教应：概念先讲清 → 让作者动手 → 审阅纠错。
- 分段小步、每步给可运行验证点、等反馈再继续，不要一次性倾倒大量内容。
- 报错先要完整 Traceback 再对症下药。排查接口用 `curl -i` 而非只看 Swagger 示例。
- 关键概念（JWT/异步/RAG/Agent）随代码顺带解释并埋面试题。
